# Touchstone 销项规程

**核心事实：销项率只认 PR 级评论里的围栏申报；行内评论线程一律不计数、不报错。**

## 0. 以仓正本为准

本 skill 正本在仓 `skills/touchstone-ack/SKILL.md`；会话加载的副本可能落后数版。
开工先 diff 副本与正本，有差异**按正本执行、把涉及的小节名报给操作者**并提醒
更新副本——静默切换口径等于让操作者不知道 agent 此前按哪套旧规则做过事。
（教训：agent 按旧副本"3~5 分钟后再查"口径 270 秒长睡，正本早已是 30 秒探测制。）

## 1. 分诊：advisory ≠ 卡合并

Touchstone 评审是 advisory，**不阻止合并**；阻止合并的是 gating CI（check-runs 里的
failure）与合并冲突（见 §7）。接到"修 PR X / PR X 卡住"先查 gating CI——advisory 的 open=N **不是**
待修缺陷数。有可本地跑的闸/测试/脚本先在目标分支本地复现（一行命令常直接吐
根因），API 状态只作辅助。确认卡的就是 advisory（或用户只要清意见）才进本流程。

## 2. 申报格式（唯一有效渠道）

PR 级评论 + 围栏块：

````
```touchstone-ack
PRA-REVIEW:path/file.py:123: done: 已修复(commit)。改了什么、为何、如何验证
PRA-GENERAL:path/file.py:45: waived: 反证——可核查事实（代码行引用/实测输出/文档）
DUP-001:path/file.py:1: split: https://github.com/o/r/pull/99
```
````

- 条目键 = finding 头部的 `规则ID:路径:行号`（亦在尾部 touchstone-finding 注释；
  行号为 None 时省略行段）。
- 一条评论可含多条；同根因发现逐条列出并注明"同源，随同一 commit"。
- 行内线程回复不被解析；申报必须是独立 PR 级评论。
- 多层转义易翻车：ack/PR body 一律先写临时 python 文件生成 JSON 再 `curl -d @file`。

## 3. 状态语义

| 动词 | 语义 | 机器行为 |
|---|---|---|
| `done` | 已改代码 | 下轮复检签名不再命中才落 done——**销项率自动上升的唯一来源** |
| `waived` | 驳回/豁免 | 必须带可核查反证；永不自动销项，归"待人核准"由人了结 |
| `split` | 拆到后续 PR | 必须带链接；同 waived 归待人核准 |

推论：**waived 不申报 = 永久挂着**；代码改了可不申报（机器会验）。全靠
waived/split 不触发收敛（反博弈：author 一句"waived:无所谓"不可闭环意见）。

**waived 质量线**：反证须可核查（文件行号/实测输出/既有测试名/官方文档语义），
不是"我认为没问题"。SECURITY/POSSIBLE_ISSUE/正确性类默认**先假设为真**，读码 +
实测反证才许 waived——"前面几条都是 FP"不是下一条也是 FP 的证据（惯性 waived
放过过真缺陷）。

## 4. 时序（最易错）

Touchstone 在 push 触发的复检里只读**运行启动时已存在**的申报。正确顺序：
**改码 → 提交 → 发 ack 评论（并空提交触发评审） → 推送**。推送后补发 ack 本轮不计，白等一轮。
发 ack 评论的同时补一个空提交（`git commit --allow-empty`；无代码改动的纯 ack 轮同理）——
空提交与 ack 评论同点承载触发，本次推送必触发读取该申报的复检轮；不推送则申报永不被读取。

**销项是多轮交互，不是一发即中**：每次推送触发复检，复检可能新增 findings
（评审看到修复后给出下一层意见是常态）。推送申报后**自行启动定时任务，
每 1 分钟检查一次**该 PR 最新一条 bot 评论（判新轮只认 bot `created_at`，见 §7），
有新轮即进入下一轮 改码 → 申报 → 推送；**直到 ✅ 收敛或 ⬆️ 升级到人**才停轮询。
单条工具命令内仍守 §7 的探测纪律（≤8 次 30 秒），1 分钟节奏靠跨命令的定时任务
实现，勿在单命令里死等。

**本地全量测试不必每轮跑**：销项持续多轮，中间轮的修复通常只动小面——每次
ack 前都跑全量测试是纯开销。全量测试只做两次：① 首次申报前（锁基线，起点
全绿，后续红了就是本轮改的）；② findings 清零后（终验，整链仍全绿才转人合并）。
中间轮跑改动相关的定向测试即可——§6-2 的"落进测试套件"指修复要带测试断言，
不是要求每轮全量跑。

## 5. 终局

- `✅ 收敛` = 可自动销项条目全销（done 经复验）且无新增自改发现；waived/split
  不阻塞收敛判定，归"待人核准"栏由人了结。
- `🔁 继续` = 还有可自改发现。
- `⬆️ 升级到人` = 轮次耗尽（上限 9）或无推进（销项率连续不升且无 waived/split——
  **沉默与假修在机器视角不可区分**，宁可 waived 附反证，绝不沉默）。升级不是
  失败：真缺陷清零后交人合并是正常终局。
- **停止线**（满足其一即收口转人，勿追加轮次）：同锚意见复现 ≥3 次；意见滑向
  措辞级/"防御的防御"；销项率震荡不再单调。连续两轮无真问题即可收口。

## 6. 逐条纪律

1. **先核代码再定性**。误报集中在"只看 diff hunk、看不见上下文守卫"——早几行的
   str() 包裹、早退 return、循环外守卫它都可能看不见。反证写"为何不可达/契约
   为何保证"，不写"没必要"。
2. **修复必须落进测试套件**（TEST-001 专抓临时脚本验证）；断言要能在缺陷复现时
   必挂（防 `x.index(c)>0` 类恒真）。ack 里写实测结果（输入 → 退出码/输出）。
3. **同根因合并修**，逐条申报，不为凑条数分开改。
4. **僵尸窝点**：同一文件连多轮换角度出题、新条与已反证条同族 → 第三波起批量
   waived 引用既有证据（"同窝点第 N 波，与 :X/:Y 同族同反证"）并预告升级人工。
   销项率不升反降是分母在涨，不是处置失效。
5. **消除优于加固**：评审说"转义/净化/清理不全"时先问**这条路径是否必要**。
   判据（命中即考虑删）：修复=给映射补遗漏字符；输入是任意文本；存在不经该映射
   的等价实现。删除后申报 `done` 并写明为何不采建议的加固方案（否则复核方读成
   假修），**必须留一条断言该路径不存在的测试**。边界：路径必要、仅场景行为不同
   → 按场景分流不删（判别问句：删掉后原本它保证的东西是否还有人保证？）。
6. **警惕自造回归**：守卫只包一半路径、去重留双份。后几轮的"真问题"多是前几轮
   修复的遗漏面，属正常，照修。

## 7. 合并与轮询的坑

- **PR 合并后其分支的推送不再被跟踪**；推送前确认 PR 仍 open。已发生 → 从 main
  切分支 cherry-pick 落下的提交另开 PR。合并生效核对用 grep 查关键标识在 main，
  不只看 git log（哈希会骗人）。
- **合并冲突先于 ack**：PR 冲突（API `mergeable_state=dirty`，取 PR 对象的
  mergeable 字段；null 表示尚在计算，稍后重查）时，先 rebase/合 main 解冲突
  再进 ack 流程——解冲突本身改代码、会触发新一轮评审，先 ack 再解等于申报
  刚被消费就作废；且冲突不除，收敛了也无法合入。
- **判新轮只认该 PR 最新一条 bot 评论的 created_at**，绝不用 PR updated_at（自己
  的 push/ack 也刷它）。清单自足累积，永远只需最新一条 bot 评论，勿全量翻史。
- 复检 push 即时触发（30s~1min 出轮），拥堵可达小时级——**按探测次数计不按墙钟**。
  单条工具命令内 ≤8 次 30 秒探测（死等会被单命令超时整杀且丢中间产出）。
- 空闲队列 **20 探**无新轮且 PR 未处终态（已收敛/升级后再推空提交会再生一轮、
  可能新增 FP）→ 推空提交重触发（已发 ack 不必重发）；拥堵期不盲目重触发，用
  巡检循环持续观测替代。
- **多 PR 调度**：单一巡检循环（30~60s）遍历全部 open PR 的最新 bot created_at，
  先出轮先处理，推完即切下一单。增量拉取 `comments?since=<上次已见>` 初筛 +
  **按 comment id 去重**（since 匹配 updated_at，旧评论被编辑也返回；不用 +1s
  偏移，会漏同秒新评论）；命中后仍按 bot created_at 判新轮。
- CI 等待锚 **head_sha 不锚分支**（同分支新旧 run 排队窗口不误判）；
  completed+action_required = 需人工批准的阻塞终局——报告转人，本轮不等待。

## 8. 申报前自查

- [ ] PR 级评论、围栏语言 touchstone-ack、键与 finding 头部一致
- [ ] waived 带可核查反证；done 带 commit 与实测结果
- [ ] 代码改动有测试断言（防 TEST-001）
- [ ] ack 在推送之前；纯 ack 轮有空提交承载
- [ ] 判新轮用 bot created_at；单命令 ≤8 探、不按墙钟
- [ ] PR 无合并冲突（mergeable_state=dirty 先解冲突再申报，见 §7）
- [ ] 推送前确认 PR 仍 open；已对照仓正本（§0）
